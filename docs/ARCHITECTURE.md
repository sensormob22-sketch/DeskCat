# Архитектура

## Рендерер: Panda3D + panda3d-gltf

Выбран Python-движок Panda3D с импортёром panda3d-gltf для glTF 2.0 / GLB.
Он поддерживает скелетную анимацию и Actor с управлением весами клипов. Это
позволяет сохранять Python-контроллер состояний и не вводить отдельный игровой
движок или браузер. Qt Quick 3D проще интегрировать с Qt, но управление импортом
и смешиванием произвольных скелетных клипов через Python менее прямое.

Рендерер пока **не реализован**. Extras закрепляют версии будущих зависимостей;
`AnimatedRenderer` задаёт границу интеграции, текущий QWidget рисует заглушку.
Фотореализм потребует отдельно настроенного PBR-пайплайна (например, собственного
шейдера или совместимого simplepbr), IBL, tone mapping, качественных текстур,
шерсти и теней. Один импорт GLB не обеспечивает фотореализм.

## Поток кадра

QTimer → контроллер поведения → StateMachine → веса клипов → Panda3D Actor →
RGBA offscreen render target → readback → owned QImage → QPainter в PySide6.
Начать с одного Qt-потока, ручного шага Panda3D task manager; не запускать второй
блокирующий event loop. При необходимости вынести рендеринг в отдельный поток
с принадлежащим ему GPU-контекстом и передавать только готовые кадры.

У render target alpha=0 в фоне; проверить premultiplied alpha и вертикальную
ориентацию readback. Размер render target = логический размер окна × DPR.
Камеру кадрировать по bounds модели, нормализовать реальные метры, центрировать
pivot у лап. GLB использует Y-up; импортёр / адаптер должен согласовать это с
Z-up Panda3D ровно один раз. Перемещение окна — в логических пикселях, клипы walk
— in-place, чтобы не дублировать root motion. Readback дорог: измерить задержку
и загрузку GPU, затем при необходимости заменить на GPU-sharing.

Qt окно: FramelessWindowHint + WindowStaysOnTopHint + Tool,
WA_TranslucentBackground. На Windows проверить DWM, смешанный DPI, несколько
мониторов и прозрачный hit testing. Это обычное окно поверх desktop, без внедрения
в Explorer. Поведение над exclusive fullscreen не гарантируется.

## Поведение и анимация

StateMachine содержит idle, walk, sit, stand_up, groom, sleep, drag.
При переходе сохраняет текущие веса и смешивает их с целью за 0.3 с (smoothstep),
в том числе при прерванном переходе. stand_up возвращается в idle через 0.8 с;
в 3D использовать фактическую длину клипа. Drag временно останавливает ходьбу и
после отпускания восстанавливает предыдущее состояние.

В прототипе idle/walk/sit/sleep визуально представлены простыми изменениями позы;
groom/stand_up/drag пока имеют только состояние и переход весов. Для 3D нужны
клипы одной и той же иерархии костей, одинаковая bind pose и карта state → clip.
При отсутствии клипа явно сообщать о нём и использовать idle, не выдумывать анимацию.

## Ollama

`integrations/ollama.py` содержит выключенную по умолчанию конфигурацию и контракт
DialogueService. Следующий этап: локальный POST `/api/chat`, выбранная пользователем
модель, timeout, отмена, обработка недоступности сервиса. Выполнять запросы в
worker thread; отдавать ответы сигналами Qt. Запуск сейчас не делает сетевых запросов,
не требует Ollama и не посылает пользовательские данные.
