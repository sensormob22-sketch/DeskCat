## Растяжение и сжатие

Метрики рассчитаны по реальным исходным рёбрам и площадям треугольников; ratio 1 означает rest. Для каждого региона в JSON есть min/max, P1/P5/P50/P95/P99, площадь < половины и > удвоенной. ROI считаются по граням/рёбрам, касающимся указанного набора вершин; хвост и широкая REVIEW-область бедра могут пересекаться. Эти ROI не разрешают менять дополнительные вершины.

| C2 patch, +15° | v6 | C2 trial |
|---|---:|---:|
| Минимум area ratio | 0.290680 | **0.287983** |
| Минимум edge ratio | 0.619295 | **0.615597** |
| Максимум edge ratio | 1.121103 | **1.127651** |
| Треугольников с площадью < половины rest | 2 | 2 |
| Медиана area ratio | 0.860398 | 0.857599 |

Худший треугольник сохраняет 29.07% → 28.80% исходной площади: локальное сжатие усилилось. Максимальное растяжение ребра 12.11% → 12.77%. Некоторые верхние перцентили улучшаются, но это не компенсирует сохранённое пересечение и ухудшение экстремумов. При отрицательной комбинированной позе та же тенденция. C1 и центральный pelvis ROI сохраняют метрики; старые тяжёлые проблемы левого бедра (51 / 162 пары в его отдельных пробах) остаются.

Мелкие исходные треугольники шерсти могут усиливать экстремальные ratio: они приведены вместе с перцентилями, полными парами и изображениями, без автоматического удаления геометрии.

## Проверка экспортёра и фактического GLB

Blender 4.3.2 отбрасывает влияния **≤0.0001**, затем нормирует оставшиеся. Из исходного pre-export skin теряются **12343** положительных влияния; у **7530** source vertices отличие >1e-7, максимальная компонента **0.000179112**. Это прежний эффект v6, не расширение данной маски. На утверждённых 21 вершине **0 потерянных влияний, максимальная разница pre/post-export 0**. Экспортированные веса остальных вершин точно совпадают с предыдущим v6 GLB: [проверка](export_baseline_rounding.json).

Первый диагностический экспорт выявил отдельную ошибку конфигурации: Blender включил унаследованный HEAT-атрибут как `COLOR_0`, и превью стало ложноколёрным. Этот вариант **отклонён и оставлен только в игнорируемых artifacts**. В единственном конечном GLB экспорт vertex colors явно выключен (`NONE`), без повторного применения/изменения весов и без правки текстур или сцены. [Аудит исправления настройки экспорта](export_color_audit.json). Затем **заново** выполнены все actual-export позы, изображения, аудит и Validator. HEAT-слои Blender-сцены сохранены для исходного контекста.

Panda3D управляет 17 реальными CharacterJoint фактического GLB. Учтено изменение локальных осей костей экспортёром: используются реальные bind-повороты Panda и ось покоя, а не прямое копирование Blender local matrices. Проверка rest/bind <1e-7; ошибка позиций относительно pre-export Blender ≤ **9.29e-6** (включает экспортное отсечение и float32), новые пары во всех позах совпали. Между экспортами вне 21 ID есть только численный шум вычисления bind/blend, максимум **8.43e-8**; экспортированные веса этих вершин одинаковы. Это отделено от строго нулевой разницы Blender-сцен.

[Preservation audit](export_preservation.json): 100790 ориентированных треугольников с точными position+UV сигнатурами сохранены; позиционный и UV component error 0; три исходных texture payload SHA совпадают; семантика texture slots материалов сохранена. Экспорт добавляет четыре split vertices (58450 → 58454), переставляет image/material индексы и переименовывает изображения, меняет sampler declarations, убирает `KHR_materials_volume` и `FB_ngon_encoding`. JSON материалов поэтому не идентичен; не заявляется полная PBR-эквивалентность. Максимальная разница нормалей относительно localprep 0.7675°, ни одной >1°. COLOR_0 в конечном файле отсутствует.

[Khronos GLB Validator](glb_validator.json): 0 ошибок, 1 предупреждение `MESH_PRIMITIVE_GENERATED_TANGENT_SPACE`. Tangent space генерируется runtime; его переносимость между реализациями не подтверждена.

## Проверки и остановка

**96 тестов прошли, включая 5 новых, 24.50 с**. [Отчёт тестов](test_results.json). Linux cloud worker; Blender 4.3.2, Python 3.12, Panda3D 1.10.15 / panda3d-gltf 1.3.0, PySide6 offscreen, llvmpipe. Windows GUI и ручное управление в реальной графической сессии не проверялись.

Инструменты: `blender_c2_trial.py` (обязательный dry-run, одна новая сцена, checkpoint/rollback на ошибке назначения, отказ при существующих outputs), `panda_c2_trial.py` (actual CharacterJoint captures), `blender_audit_panda_c2.py`, `render_c2_trial.py`, `blender_export_c2_diagnostic.py` (только настройки экспорта, без назначения весов). Прогон всей процедуры повторно не нужен и не является разрешением на ещё одну правку. Для rollback результата достаточно исключить эти две trial-копии и снова открыть неизменённую исходную сцену; runtime модель не переключалась.

**Решение: REJECT_EXACT_STAGE10_PROPOSAL_AFTER_ONE_TRIAL.** Не увеличивать шаг сглаживания, не добавлять C1/left_hip, не оптимизировать автоматически. Возможный следующий технический разбор — ручной анатомический контур хвостовой поверхности, ориентация/pivot кости и взаимодействие отдельных шерстяных слоёв в C2. Это лишь направление для нового review, не новое предложение весов и не выполненная операция. Tripo, платные сервисы, походка и merge не использовались.
