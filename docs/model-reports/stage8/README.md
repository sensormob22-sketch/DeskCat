# Этап 8 — один цикл исправления экспериментальных весов

**Результат: v6 отклонён для production; автоматическую настройку остановили после одного цикла.** Хвост и изолированный таз заметно улучшились численно, но остаются складки и серьёзные регрессии грудного отдела и левого тазобедренного сустава. Это диагностическая копия, не готовый риг и не анимация кошки.

База: `a14fd2f`, ветка `feature/tripo-cat`. Прочитан [review PR #2](https://github.com/sensormob22-sketch/DeskCat/pull/2#issuecomment-6103082990). Ни Tripo, ни платные операции не использовались. Merge не выполнялся.

[Манифест четырёх защищённых GLB](preserved_manifest.json): оригинал, rigprep, localprep и skinprobe_v5 побайтно прежние. Новая модель: [`deskcat_calico_h25_v1_skinprobe_v6.glb`](../../../assets/3d/tripo/deskcat_calico_h25_v1_skinprobe_v6.glb). SHA-256: `e6ea0f3cdbf0230233cddf259d720fac61aab481cb134eb06ac3a6d2108cd51d`.

Веса менялись на отдельной импортированной копии localprep. Изменено **0 координат вершин**, **0 UV**, **0 байт текстур**; 100790 ориентированных треугольников position+UV совпадают точно. Blender разбил четыре вершины: 58450 → 58454, без изменения поверхности. Мордочка защищена root: 6026 исходных вершин, ни одной с посторонним весом. Никакого remesh, изменения длины хвоста, зеркалирования или замены окраса.

## Диагноз v5: где именно возникли пересечения

[Полные локализации v5](v5/diagnostics.json) и [v6](v6/diagnostics.json) содержат для каждой из 43 поз stable `source_face_pair`, точные source/canonical vertex IDs, координаты, AABB кластеров, доминирующую кость, **все положительные веса**, отношение площади каждой затронутой грани и различие весов между пересекающимися гранями. Номера относятся к треугольникам localprep (после удаления прежней вырожденной грани), не к переупорядоченному экспорту Blender. Число пар не равно числу анатомических дефектов.

## Один зафиксированный вариант v6

- Хвост: связная поверхность от фактической крайней вершины, внутри локального 3D-коридора `X>.27, Y<.285, |Z|<.085`; 5374 canonical вершины. Коридор только выделяет компоненту. Влияние рассчитывается по **геодезическому расстоянию вдоль рёбер** от её границы с тазом, `smoothstep(distance/.09)`, а не глобальному X. Переход pelvis → tail_base; на другой поверхности и четырёх опорных заплатках вес tail_base строго 0. [Аудит маски](v6/weight_mask_audit.json). Силуэт и heatmap проверены; точный проксимальный контур ещё нуждается в ручной разметке.
- Корпус: вместо трёх конкурирующих гауссиан + root введено распределение с суммой 1 вдоль корпуса и иерархия `root → thoracic → lumbar → pelvis`; передние плечи дочерние thoracic, hips и tail дочерние pelvis. Исходные проверяемые pivots сохранены, чтобы не подменять сравнение новой анатомией. `use_connect=False`; это временная иерархия, не утверждённая окончательная схема.
- Конечности: шире и плавнее расстояние до фактических асимметричных цепочек (.07 вместо .048), smoothstep у стыков с корпусом. Положение правых и левых суставов разное и взято из этапов 6/7. Жёсткие нижние заплатки сохраняются; их граница остаётся проблемой.
- До четырёх нормированных влияний на вершину; у совпадающих шовных копий идентичные веса. Дополнительные сегменты хвоста не добавлялись: необходима ручная проверка центральной линии и места изгиба, а новые автоматические pivots проблему переходной кожи не подтверждают.

## Экспорт и проверки

JSON материалов отличается перестановкой индексов изображений/текстур; sampler 3×{} заменён одним явным LINEAR/LINEAR_MIPMAP_LINEAR. Убраны необязательные декларации KHR_materials_volume и FB_ngon_encoding. Нормали: максимальное отличие .7675°, P99 .006562°, как в v5; это не замена текстур. [Bind audit](v6/skin_bind_audit.json): максимальная rest ошибка 9.87e-8; 17 костей, один skin, 0 клипов.

[Khronos Validator](v6/validation.json): 0 ошибок, 1 предупреждение `MESH_PRIMITIVE_GENERATED_TANGENT_SPACE`; явные тангенсы отсутствуют, runtime shading не гарантирован одинаковым. Проверка формата не принимает деформацию.

Linux: Blender 4.3.2 headless, Python 3.12, Panda3D 1.10.15 + panda3d-gltf 1.3.0, PySide6 6.8.3; software llvmpipe. **77 тестов прошли** (включая 8 новых, сверяющих фактические skin/weights/защищённые файлы). [Результат тестов](test_results.json). [Qt+Panda smoke](linux_smoke.json): конечный v6 импортирован, окно visible, 240×220, DPR1, corner alpha0, все семь отсутствующих клипов явно NOT played. Это Linux offscreen, не доказательство прозрачности Windows 11. Windows CI в этом этапе не запускался; реальная Windows 11, DPI150%, IK, контакт с полом и полноценный PBR не проверялись.

## Следующая работа: только после ручной проверки

1. В Blender открыть **отдельную** диагностическую сцену v6; заморозить geometry/UV и три текстуры. Выделить source IDs трёх кластеров хвоста из v6/diagnostics.json. Вручную нарисовать несколько поперечных колец pelvis → tail_base, не распространяя вес в бедро; проверить ±5°/±10°/±15° с обоих боков и снизу. Уточнить центральную линию и лишь затем добавить 2–3 tail сегмента для следующих изгибов, сохраняя длину и полосы.
2. По `isolated_thoracic` и `isolated_hip_HL_opposite` вручную ограничить thoracic/lumbar на животе и связь pelvis/бедра. Иерархию применять с границами влияния, согласованными с передачей движения; не закреплять кожу на root посреди движущейся цепочки. Отдельно проверить правое плечо (20 новых пар) и левое бедро (51/162), без зеркальной замены исходной асимметрии.
3. Расширить переходы жёстких опорных заплаток вручную: front_FR и hind_HR пересечения находятся у низких границ, а не доказанно у локтя/колена. Сохранять форму опоры, не менять положение лап автоматическим выпрямлением.
4. Если ручной вес на тонких выступах всё равно даёт складки, локально проверить геометрию конкретных source faces: отличить допустимую шерсть от наложенного треугольника. Любая правка — новый GLB, отдельные UV/texture/face-preservation измерения; глобальный remesh не нужен.
5. Альтернатива — небольшая анатомическая деформационная cage с переносом движения на детальную шерстяную поверхность, либо тест dual-quaternion в Blender для объёма. Это отдельный эксперимент: Blender preserve-volume не эквивалентен обычному glTF/Panda LBS, нужно доказать перенос/совместимость. Не объявлять его поддерживаемым runtime без проверки.

До прохождения этих контрольных поз не создавать походку, сидение и умывание. Серьёзные дефекты после одного цикла задокументированы; второй автоматический цикл не выполнялся.

Из корня репозитория, в новых путях (builder отказывается перезаписывать GLB и каталог):

```bash

blender -b --factory-startup --python-exit-code 1 --python tools/blender_deformation_probe.py -- --weight-version v6 --holdouts --output artifacts/reproduce_v6 --export artifacts/reproduce_v6.glb

blender -b --python-exit-code 1 --python tools/blender_skin_weight_audit.py -- --source assets/3d/tripo/deskcat_calico_h25_v1_localprep.glb --weights artifacts/reproduce_v6/weights.npz --paw-review docs/model-reports/stage6/localprep_geometry_review.json --output artifacts/reproduce_v6/weight_mask_audit.json
.venv/bin/python tools/render_rig_inspection.py artifacts/reproduce_v6/tail_bend.glb --reference-model assets/3d/tripo/deskcat_calico_h25_v1_localprep.glb --output artifacts/reproduce_v6/views-tail --only-views tail_base tail_transition
.venv/bin/python tools/skin_export_audit.py assets/3d/tripo/deskcat_calico_h25_v1_localprep.glb artifacts/reproduce_v6.glb --output artifacts/reproduce_v6/export_audit.json
.venv/bin/python tools/skin_bind_audit.py artifacts/reproduce_v6.glb --output artifacts/reproduce_v6/bind_audit.json
QT_QPA_PLATFORM=offscreen .venv/bin/python -m deskcat --renderer panda --model assets/3d/tripo/deskcat_calico_h25_v1_skinprobe_v6.glb --smoke-test
.venv/bin/python -m pytest -q
```

Сцены .blend, массивы весов NPZ и статические GLB поз в `artifacts/` игнорируются Git; в репозитории сохранены конечный v6, измерения, source IDs и PNG. Файлы моделей предыдущих этапов и все семь работающих функций приложения не заменялись.
